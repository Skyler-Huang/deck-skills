# 反面清单：真实踩过的坑

这份清单来自一次被用户连续否掉四版才做对的任务，以及技能包开发过程中实测触发的 bug。**每条都有现象、根因、正确做法**。用户否掉一版要重做时，先读这里再动手。

---

## A. 理解类（最贵，会导致整版返工）

### A1. 把「贴近我的风格」理解成「换一套更好看的风格」

- **现象**：用户说「不要改我背景风格！你没看见产品风格与我 PPT 一样吗」，要求全部撤销重做。
- **根因**：擅自把浅蓝→暖白渐变换成了米黄纸纹插画背景，觉得"更精致"。
- **正确做法**：渐变色值必须与原稿**逐字一致**。底色用代码还原，生图只允许贡献装饰纹理（`make_background.py --overlay` 走高通）。用户说"贴近风格"就是字面意思。

### A2. 擅自加产品截图和二维码

- **现象**：「擅自加产品截图和二维码一点都不美观」。
- **根因**：把"用项目里的元素"理解成"把界面贴上去"，还顺手加了二维码。
- **正确做法**：项目元素要**抽象成同风格的装饰贴片**（放大镜、卡片、信纸、星簇），不是贴界面截图。产品截图、二维码、页眉胶囊、进度条都属于「新增可见对象」，必须用户明确点头。

### A3. 没去看用户点名的 GitHub 项目

- **现象**：「说了 github 上的项目你看看」。
- **根因**：只搜了在线体验页，没找到仓库就自己编元素。
- **正确做法**：仓库名可能与产品空间名 / 作者名完全不同（真实案例里在线空间叫 `A/reader`，代码仓库叫 `B/essay-*`，靠作者名的相似性才对上）。用多关键词搜、`gh api`、直接 `git clone`、CDN 文件树逐层找。读 `README.md` 与 `app.css` 常能发现**锁定的色板**和「画面由排版、SVG 与 CSS 生成，不是 AI 生成」这类硬规范。

### A4. 装饰淡到看不见

- **现象**：「没有看得出来的美化」「你这个不明显」。
- **根因**：把装饰压到 alpha 十几的"氛围级"，生怕改风格，结果等于没做。
- **正确做法**：判断标准是**并排对比时四角能明确指出新增了什么**，同时中部正文区渲染差异接近 0。`verify_zero_change.py` 的「边缘差异 > 0.3」就是这条的量化红线。提高四角可见度和语义关联，而不是动正文区。

### A5. 改了文件名

- **现象**：「我文件名被你改了，学校，姓名那个格式呢」。
- **根因**：另存成 `<产品名>-配图美化版.pptx`。
- **正确做法**：「不改整体框架」包含不改文件名。交付与输入同名；要出新版就另存并明确告知。

### A6. 范围没确认就"顺手多做一些"

- **现象**：用户最后划定了「①做 ②顺带做 ③④不做」。
- **根因**：前几轮反复自作主张加东西。
- **正确做法**：把可选做法编号列出请用户勾选，没选的一律不做。别把"顺手"当贴心。

## B. 技术类（会导致效果出错或误判）

### B1. 内置截图工具缓存，验证结论全错

- **现象**：装配后渲染像素差异恒为 0；连新增一张**纯红不透明矩形**、把它放最顶层，都返回原稿像素；原稿第 18 页自带的界面截图也渲染成白板。换文件名、重开编辑会话都无效。
- **根因**：渲染服务对同一路径/内容做了缓存，不重绘新增图片与形状。
- **正确做法**：用 **LibreOffice 独立渲染**（`soffice --headless --convert-to pdf` + `pdftoppm`），每次用新的临时文件名。不要用内置截图工具验证新增内容。XML 结构校验与独立渲染是两条互补的可靠路径。

### B2. 「假透明」生图贴出补丁方块

- **现象**：申请 `background=transparent` 的贴片元素贴进 PPT 后带一块浅灰白底方块，非常突兀。
- **根因**：生图返回的是 RGB + 浅灰白棋盘底，不是真 alpha；直接缩放色键抠图会留斑驳。
- **正确做法**：用 `strip_watermark.py --cutout` 做**四边连通域 flood-fill**（只删与边缘连通的背景，主体内部的白色纸卡会被保留），再做边缘羽化与开运算去噪。

### B3. 右下角「AI生成」水印

- **现象**：每张生图右下角都有平台水印。
- **正确做法**：底图阶段清除。`strip_watermark.py` 对不透明底图用「水印区上方一行渐变像素按列向下拉伸」补齐（不制造透明洞），对透明元素直接把该块 alpha 清零。用 `--audit` 的对比度拉伸图确认残留 —— 只有拉伸 200 倍才显出的痕迹，正常观看不可见，可接受。

### B4. 媒体去重陷阱：替换 media 连坐其它页

- **现象**：20 张背景图实际只有 11 张唯一（多页共用同一 `r:embed`）。
- **根因**：`python-pptx` 会自动对相同图片去重。
- **正确做法**：**从原稿重新装配**（`apply_background.py`），不要按页替换 `ppt/media/` 里的文件。脚本会检测输入是否已含装饰层并拒绝执行。

### B5. 固定角落 = 必翻车

- **现象**：某页左下角配图压住两行小字；封面左下角放大镜线稿被白卡片切成一半，显得残缺。
- **根因**：凭直觉统一放某个角落；用形状 bbox 判断"空不空"时，横跨整页的标题框会被误判成"满"，结果全挤到右上。
- **正确做法**：用**原稿真实渲染图**算四角候选区里「与背景色差 > 阈值」的像素占比（`pick_corners.py`）。若某角落全稿统一留白，统一放那里反而像设计过的版式。封面/尾页已有主视觉时只放极轻星点，别再叠放大镜。

### B6. 装饰叠在预览图最上层造成误判

- **现象**：合成预览里装饰盖在卡片上，误以为"遮挡文字"。
- **根因**：预览时把装饰层 `alpha_composite` 到渲染图**最上层**。
- **正确做法**：真实 PPT 里装饰在内容之下，白卡片会盖住它。要看真实层级，装配后用独立渲染器出图。

### B7. 注入 transition 时原地读写同一个 zip 导致文件损坏

- **现象**：`zipfile.BadZipFile: Truncated file header`，随后 PPT 打不开（`KeyError: no member '/[Content_Types].xml'`）。
- **根因**：`ZipFile(path)` 读 + `ZipFile(path, "w")` 写指向同一文件，写模式一打开就截断源文件。
- **正确做法**：一次性把所有条目读进内存 → 写 `*.tmp` → `os.replace()` 原子替换。`inject_transitions.py` 已修。

### B8. 「transition 残留」的字符串检测误报

- **现象**：`--remove` 回滚后 `'transition' in slide_xml` 仍为 True，以为没删干净。
- **根因**：原稿 `p:timing` 里本来就有 `<p:animEffect transition="in" filter="fade">` 这样的**属性**，是自带的进入动画，本就该保留。
- **正确做法**：判断 `p:transition` **元素**（按命名空间查找），不要对整段 XML 做子串匹配。

### B9. 注入动画顺序错，PowerPoint 提示修复

- **根因**：`CT_Slide` 子元素有固定顺序，且手写 `p:timing` 极易破坏原动画。
- **正确做法**：`p:transition` 插在 `clrMapOvr` 之后、`timing` 之前；**只加切换，不碰 `p:timing`**；注入前后比对 `p:timing` 序列化字节。

### B10. accents 按频次排序，星星画成暗色

- **现象**：`inspect_deck.py` 自动提取的色板把墨蓝 `3F6478` 排在 `accents` 第一位，生成的四角星偏暗。
- **正确做法**：脚本已改为「已知品牌亮色（黄/粉/青/绿/橙）优先 + 剔除 ink 与底色」，但仍要**人工复核 `assets/color-tokens.json`**，按项目 CSS 的顺序调整。

## C. 沟通类

### C1. 替用户打包票说兼容

手写 OOXML 只能验证到「LibreOffice 能转 PDF、XML 合法」。沙箱没有 PowerPoint/WPS，必须明说：「请在你实际演示的软件里打开确认，有没有『需要修复』提示」。

### C2. 交付时没说「哪些没做」

用户没勾的选项、动画的兼容提醒、口味档位（可再调淡/调浓），都要在交付说明里写清楚。

### C3. 用 AI 生图前不说明积分消耗

生图按张消耗积分。开工前告知张数与大致区间，别让用户事后才发现。

---

## 一句话

**前四版全错在"我以为更好看"，后几版全错在"验证工具骗了我"和"细节没兜住"。** 风格问题靠溯源和色值锁定解决，验证问题靠独立渲染和 XML 字节比对解决，其余靠这份清单逐条避让。
